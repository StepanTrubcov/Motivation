# Локальные изображения достижений

Перед любыми изменениями приложения обязательно выполнить `npm run backup` из `my-app/client` и убедиться, что новый JSON-файл существует и содержит массивы users, goals, achievements. Обычный бэкап теперь не удаляет предыдущие копии и возвращает ошибку при неудаче. Файлы копий содержат личные данные: не публиковать их.

31 статичная картинка находится в public/Image/achievements. GIF остаются сетевыми. Точное соответствие старых URL новым путям хранится в src/lib/achievement-images.json. На клиенте старые URL поддерживаются до миграции; генераторы карточек читают эти файлы с диска. Для Vercel файлы включены в tracing.

## Текущий режим: только локальная разработка

По указанию владельца проекта изменения остаются только на ПК: не делать push, не публиковать на Vercel и не запускать миграцию удалённой БД. Старые сетевые значения image преобразуются в локальные пути в ответе API-клиента без записи в БД; уже обновлённые пути остаются прежними. GIF не преобразуются.

Для проверки использовались сборка, статичные HTTP-файлы и генераторы карточек без запросов к пользовательским API. Полный запуск интерфейса с текущими переменными окружения может выполнять обычные записи в удалённую БД (профиль, инициализация, достижения), поэтому для свободного тестирования нужна отдельная тестовая БД.

## Будущая миграция — только после отдельного разрешения владельца

1. Проверить `npm run build`, опубликовать подготовленную версию на Vercel обычным способом. Не запускать массовые update-achievements: это изменение не требует изменения статусов или других полей.
2. Просмотр живой БД без записи: `node scripts/migrate-achievement-images.mjs`.
3. Применение ПОСЛЕ публикации: `node scripts/migrate-achievement-images.mjs --apply --base-url https://АДРЕС-ПРИЛОЖЕНИЯ`.

Скрипт сначала проверит HTTP-доступность и SHA-256 всех 31 опубликованных файлов, затем выполнит npm run backup и проверит новую копию. Сохраняет журнал прежних ссылок в scripts/achievement-image-migrations (исключён из Git), меняет только image транзакцией и сравнивает записи целиком. Сохраняет также updatedAt. При неизвестных URL, конфликте или отличии других полей операция отменяется. Повторный запуск не меняет уже локальные ссылки. Пользователи и цели не обновляются.

Просмотр сохранённой копии без подключения к БД:
`node scripts/migrate-achievement-images.mjs --backup scripts/backups/ИМЯ-КОПИИ.json`

Откат только image, с новым предварительным бэкапом:
`node scripts/migrate-achievement-images.mjs --rollback scripts/achievement-image-migrations/ИМЯ-ЖУРНАЛА.json`

GIF, идентификаторы, статусы, очки, условия и прогресс не меняются. Применение и откат требуют сетевого доступа к БД. Пока файлы не опубликованы, живую БД не мигрировать.
